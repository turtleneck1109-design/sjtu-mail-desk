# 交邮 · SJTU Mail Desk

一个在 Mac 本机运行的中文批量邮件工作台。将多封 `.eml` 草稿拖入浏览器，核对各自的收件人、正文和 Excel 等附件，再通过 SMTP 逐封提交。

运行时仅使用 Python 标准库，不需要安装第三方 Python 包。HTML、CSS 和 JavaScript 也不依赖外部服务。

## 快速开始

环境要求：macOS、Python 3.9 或以上版本。本项目已在 Python 3.14.4 环境测试。

下载或克隆仓库后，在 Finder 中双击：

| 启动入口 | 用途 |
| --- | --- |
| `演示启动.command` | 自带示例邮件，模拟整个流程，不连接 SMTP，不需要真实密码 |
| `启动交邮.command` | 使用真实草稿的正式工作区；打开、导入和预览均不会自动发送 |

启动后会自动打开默认浏览器。请保持启动终端开启；关闭前先在页面停止后续发送，再在终端按 `Control+C`。

也可以在项目目录执行：

```sh
python3 app.py --demo
```

如果下载的启动文件没有可执行权限，可在项目目录恢复权限：

```sh
chmod +x *.command
```

## 功能

- 批量拖入或选择 `.eml` 文件，按内容摘要去重。
- 展示收件人、抄送、密送、中文主题、正文和附件信息。
- 隔离 HTML 预览，禁用脚本、远程图片、跳转和嵌入内容。
- 支持保存附件；保留原稿及原有 MIME 正文和附件。
- 单封改投测试邮箱，确认实际投递清单后才提交。
- 逐封进度、停止后续发送、搜索和状态筛选。
- SQLite 持久化记录，CSV 导出；重启后保留去重状态。
- 部分拒收只重试明确失败的地址，已接受地址不重复提交。
- 提交断线或意外中断时锁定结果未知的地址，人工核对后可解除锁定。
- 阻止重复点击和同一工作目录的多个实例并行发送。

## 正式使用流程

1. 双击 `启动交邮.command`，导入自己的 `.eml` 草稿。
2. 点击邮件详情，核对 To/Cc/Bcc、正文和附件；修正检查未通过的草稿后重新导入。
3. 填写 jAccount 用户名，不含 `@sjtu.edu.cn`。
4. 需要试发时，先取消全选，只勾选一封并填写自己的测试邮箱。
5. 批量发送前核对弹窗中的实际投递地址，输入指定确认文字和密码。
6. 查看进度与记录；需要停止时点击“停止后续发送”。正在提交的一封仍可能完成，不能撤回。

SMTP 使用用户提供的 `mail.sjtu.edu.cn:465` / SSL/TLS 配置，启用证书验证；本项目开发测试未连接学校服务器验证配置、认证或投递。

## 数据与隐私

正式数据保存在 `data/`，演示数据保存在 `demo_data/`，两者互相独立。

这些目录包含导入的邮件副本、SQLite 状态数据库与导出结果，均已在 `.gitignore` 中排除。邮件文件、表格、日志、环境配置和常见密钥文件也默认排除。仓库仅包含程序、示例生成器、测试与说明文件。

密码只用于当前任务的内存，不写入日志、数据库或浏览器存储。服务仅监听 `127.0.0.1`，校验随机访问令牌和请求来源。

备份和迁移前先关闭服务，再保留整个工作目录及状态数据库。删除数据库会丢失历史去重依据。复制出的不同工作目录不共享去重状态。

## 结果如何理解

| 状态 | 处理方式 |
| --- | --- |
| 待发送 | 可以预览确认后提交 |
| 已接受 | SMTP 服务器接受了提交，自动跳过 |
| 部分接受 | 仅明确失败或未尝试的地址可再次提交 |
| 明确失败 | 核对原因后可重新预览发送 |
| 待核对 | 默认锁定，不自动重试 |
| 检查未通过 | 修正原始草稿后重新导入 |

“已接受”不代表最终送达。SMTP 提交不保证出现在网页邮箱的“已发送”文件夹中，不能仅凭那里没有记录就决定重发。

## 测试

```sh
python3 -m unittest discover -s tests -v
node --test tests/test_ui.js
```

共 46 项自动化测试通过：33 项邮件与本机接口测试、3 项 Mac 启动入口测试、10 项离线界面逻辑测试。所有提交测试使用模拟 SMTP 对象，没有发送真实邮件。

Node.js 只用于开发者运行界面逻辑测试，普通使用不需要。界面逻辑测试不是浏览器渲染测试；开发时浏览器预览受访问权限限制，未完成自动化视觉验收。用户已在本机启动试用成功。

## 第一版范围

单个 `.eml` 文件最多 32 MB，一次最多确认 1000 封；默认发送间隔 2 秒。去重基于文件字节内容，重新导出导致内容变化的邮件会视为新草稿。支持常规 ASCII 邮箱地址及中文显示姓名、主题、正文和附件名称。

暂不包含 Excel 单元格编辑、正文编辑、定时发送、投递撤回、送达跟踪或多账号管理。

详细步骤见 [使用说明](使用说明.txt)，测试范围见 [测试报告](测试报告.txt)。
