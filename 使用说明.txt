交邮 · 本机邮件工作台 v1.0
中文界面 / macOS 双击启动 / Python 标准库

一、先体验，不发送

1. 解压 SJTU-Mail-v1.0.zip，保留 SJTU-Mail 文件夹内的全部文件。
2. 在 Finder 中双击“演示启动.command”。终端会启动本机服务，并自动打开默认浏览器。
3. 演示模式自带三封含示例 Excel 附件的草稿，以及一封缺少收件人的检查示例。
4. 演示页面所有发送操作均为模拟，不连接 SMTP，不需要真实密码。
5. 若想体验单封测试，先点击列表表头取消全选，再只勾选一封有效草稿，点击“给自己测试一封”。
6. 演示记录只保存在 demo_data 文件夹，CSV 也明确标注“模拟（未发送）”。

当前这台 Mac 已检测到 Python 3.14.4。工具运行需要 Python 3.9 或以上版本，不需要安装第三方包，也不需要 Node.js。Node.js 仅用于开发者运行界面逻辑测试。

二、使用真实草稿

双击“启动交邮.command”打开正式工作区。首次打开为空，不会自动导入演示草稿。

1. 拖入多封 .eml，或点击“选择文件”批量导入。
2. 查看主题、实际收件地址、检查结果及附件。点击主题或“查看”打开详情。
3. 正文可切换纯文本和 HTML 预览。HTML 预览禁用脚本、远程图片、外部链接和嵌入内容，外观可能与邮箱客户端略有不同；发送时保留原有 MIME 正文和附件。
4. 附件可以保存到本机。本工具不编辑或预览 Excel 单元格内容。
5. 每次打开默认选择可发送的有效草稿。问题草稿可勾选移除，但选中问题草稿时不能启动发送；修改原稿后移除旧副本，再重新导入。
6. 输入 jAccount 用户名，不带 @sjtu.edu.cn。发件地址由用户名自动生成。
7. 将来需要真实试发时，只选择一封，填入自己的测试邮箱，点击“给自己测试一封”。测试时实际信封和邮件头均改投测试地址，不向原 To/Cc/Bcc 投递。
8. 正式批量发送前点击“预览并发送所选”，核对弹窗中的实际投递清单。输入指定确认文字与密码后才会开始。取消弹窗、关闭弹窗或提交结束都会清空页面密码输入框。

本次开发与测试没有进行真实试发，也没有连接交大 SMTP 验证账号、限流或投递。

三、发送进度与停止

提交时页面显示总数、当前草稿、已接受、部分接受、明确失败、待核对数量。
点击“停止后续发送”后，不再启动下一封；已经开始的一封仍可能完成，无法撤回。
刷新同一个浏览器标签页可恢复进度。关闭浏览器标签页不等于停止后台任务。
关闭前建议先停止后续发送、等当前提交结束，再在启动终端按 Control+C。
请保持终端窗口打开，否则本机服务不可用。

重复双击同一工作目录的启动入口会提示已有实例运行，避免两个进程同时发送。演示和正式工作区独立，可以分别运行。
若复制整个工具文件夹并同时启动两个副本，它们是独立工作区，不共享去重状态；日常请固定使用同一个文件夹。

四、状态含义

待发送：没有提交记录。
已接受：该模式下的全部实际收件地址均被 SMTP 服务器接受，不表示最终送达。
部分接受：部分地址被接受；再次预览时只纳入明确失败或未尝试的地址，已接受地址不会重发。
明确失败：连接/认证阶段失败，或服务器明确拒绝。可核对原因后重新预览发送。
待核对：提交过程中连接异常，或程序在发送期间中断。默认锁定这些地址，不自动重试。
检查未通过：收件地址、邮件结构或正文编码存在问题，不能发送。

认证失败、连接失败或结果未知时会停止后续批次，避免连续尝试。
结果未知时，需结合服务端日志、回执或收件方反馈进行人工核对。
SMTP 提交不保证自动出现在网页邮箱“已发送”中，那里没有记录不能作为未发送的证据。
核对后，在邮件详情或发送记录的“人工核对与处理”入口输入“已核对，允许重试”解除锁定。这一操作会记入审计记录，且可能导致重复投递，请只在确认后使用。

五、数据保存

正式模式：SJTU-Mail/data/
演示模式：SJTU-Mail/demo_data/

每个目录包含：
- drafts/：导入的原始 .eml 副本，使用内容摘要作为文件名。
- send_results.sqlite3：发送状态、每次提交详情与人工解除锁定记录。
- send_results.csv：本批次结束后自动保存的完整结果表。
- SQLite 运行时可能产生的 -wal、-shm 文件。

网页的“导出发送记录”可随时生成最新 CSV；SQLite 是状态判断的依据。
记录包含邮件主题、收件地址、提交时间、发件地址、Message-ID 及结果，不包含密码。
界面记录时间按浏览器所在时区显示，CSV 明确使用 UTC 时间。
不要删除、替换或单独移动状态数据库后继续发同一批邮件，否则会失去历史去重依据。
备份或迁移时，先关闭服务，再复制整个工具文件夹。
从界面移除草稿会移除工具保存的副本，但保留历史提交记录，不修改你的原始文件。

六、第一版边界

- 每个 .eml 原始文件最多 32 MB，包含编码后的正文与附件。这是本工具的导入限制，不是对学校服务器限制的描述。
- 相同字节内容的草稿会在本次导入及历史发送中去重；重新导出后若文件字节发生变化，会视为新草稿，不进行语义相似度去重。
- 正式发送去重跨登录账号生效；测试发送按测试地址分别记录。成功的相同测试也不会自动重复提交。
- 只支持常规 ASCII 邮箱地址；邮箱显示姓名、主题、正文及附件名称支持中文。复杂的带引号本地部分、国际化邮箱地址暂不支持。
- 一次最多确认 1000 封；测试一次选择一封。默认间隔 2 秒，可设置 0–60 秒。
- SMTP 使用你提供的 mail.sjtu.edu.cn:465 / SSL/TLS 配置，证书验证开启。本次没有对其进行线上验证。
- 发件人、时间、Message-ID 会重建；草稿标记、旧投递验证信息、旧投递标记及回执请求头会移除，To/Cc 与正文附件在正式模式保留。Bcc 仅用于信封投递，不写入出站邮件头。
- 服务器接受不代表送达，也不提供投递撤回、送达跟踪、定时发送或账号授权管理。
- 密码只在本次任务内存中使用，不写入日志、数据库或浏览器存储；关闭本次任务后不会保存用于下次发送。
- 仅监听本机 127.0.0.1，使用随机访问令牌并检查请求来源，不提供公网或局域网访问。
